# 斗地主 0.2.0

一名玩家与两名电脑的三人牌局。支持叫地主、三张底牌、选牌/提示/出牌/不出、农民共同获胜、重发和暂停。无存档，关闭后新开局。深浅主题与窄窗口均有独立浏览器验证。

完整牌组与两家暗牌只保存在 Host 内存的规则引擎中。游戏 iframe 仅得到玩家自己的手牌、明示底牌、公开叫分/出牌记录和可推导的剩余牌数。不能通过命令指定座位或提供手牌/提示词。

每个电脑回合由 Host 按实际轮到的座位生成 `landlordSeatView`。模型只收到这个座位的手牌、已公开底牌、公开信息及由这些信息计算的合法候选动作。叫地主结束之前底牌是空数组。每次生成都是独立请求，不复用或共享两个座位的模型对话；没有工具权限。模型返回动作编号或叫分，Host 再校验并执行，完整牌组从未传给 Broker。

在平台运行工具栏分别设置“电脑 1 模型”和“电脑 2 模型”及其支持的推理水平。未绑定、限流、超时或非法动作时，使用只依赖同一座位视图的本地策略并标明原因；主动取消/切页中断不兜底出牌。电脑的候选动作最多 96 个加“不出”，策略以可用和合法为主，不保证最优打法。

叫分采用 0–3 分，3 分直接确定地主，全不叫则重新发牌。支持单、对、三张/三带一/三带二、顺子、连对、飞机及带单/带对、四带二/四带两对、炸弹和王炸；顺子不含 2 与王，飞机不能复用主体点数或把双王同时作单翅膀。没有金币、下注或现金结算。

构建：`node games/doudizhu/scripts/build.mjs`。Host 引擎/隐私测试：先构建 Host staging，再执行 `node --test packages/dsh-gamecenter/test/landlord.test.mjs`。完整实施和部署记录见 `docs/landlord-development-deployment.md`。

本目录是本地开发与受控预览工作副本，尚未发布固定提交。部署不复用扫雷的审批五元组。


游戏设置中可开启“显示剩余牌数量”，按点数显示 3–2 和两张王的数量。只从 54 张牌中扣除玩家当前手牌与公开出牌，不读取两家暗牌；明示底牌不会重复扣减。叫地主期间包含尚未分配的底牌。设置仅在当前实例内存保留。

每次 AI 提示词要求收到消息后 5 秒内选牌并只返回动作 JSON。这是模型行为要求，不保证网络/推理总耗时；请求仍有 120 秒取消上限，避免把超时本地策略冒充 AI 出牌。

本局结束后可点击“查看本局 AI 对话与 Token”，展开每个电脑回合的模型/推理档位、实际发送消息、最终回复、执行动作、耗时、错误和用量。Host 在牌局未结束时拒绝读取；不显示内部推理文本。成功、失败、取消的模型尝试均保留可用用量，并发重放不重复统计。总计信任 DSH 适配器返回的 totalTokens，缓存与推理项不再次相加；缺失用量显示“未提供”与覆盖率，已报告小计不能当完整账单。没有模型调用的本局消耗为 0。

调用记录不落盘，重发/关闭/重启清空；下一局不复用上一局记录，也不把赛后记录发给任一 AI。Host 自动全不叫重发仍计入当前开局过程。
